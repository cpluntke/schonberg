Reviewer: senior audio/web-perf pass, 2026-10-04. Priority scale: `docs/priorities.md` (P0–P3).

## Key measurements

**Timing chain (loopback, Chromium headless; `outputLatency` 30 ms + `baseLatency` 10 ms reported)**

| Simulated round-trip D | Calibrated | L2 acc @ calibrated | L2 acc @ latencyMs=0 (default) | L2 acc @ calibrated+100 ms | L1 (70 % tempo) @ calibrated |
|---|---|---|---|---|---|
| 120 ms | **121 ms** | 99.3 % | 80.2 % | 99.3 % | 99.3 % |
| 250 ms | **250 ms** | 96.9 % | **58.1 %** | 97.6 % | 99.3 % |

Conclusions:
- The chain `p.ctxTime` (window centre) → `− latencyMs` → `scoreTimeAt` (ctx clock) is correct. There is no double-counting and no sign error, and rate is handled correctly (the latency is subtracted in real time before the rate is applied).
- `position` subtracts the browser's `outputLatency` for drawing only. The calibration measures output + input latency, which is exactly what the scoring path needs, so the two are consistent.
- Calibration is accurate to about 1 ms when the signal is clean.
- The weak point is the **default**. `latencyMs` defaults to 0, so an uncalibrated singer is always scored late. Over-compensating is almost free, but under-compensating is very costly (see A1).

**Scoring realism (synthetic, standard strictness, accuracy %, pass = P)**. Full matrix: run the spec.

| Piece / part | pro singer¹ L1/L2/L3/L4 | pro, vib ±60 | pro, uncalibrated +120 ms | mediocre² | octave-below man on S |
|---|---|---|---|---|---|
| Bach BWV512 S (median note 1.05 s) | 99/96/95/89 PPPP | 97/93/91/85 PPPP | 91/77/77/72 P--- | 70/46/42/34 ---- | **50/50/50/50 ----** |
| Bruckner S (1.0 s) | 100/97/94/93 PPPP | 99/97/92/86 PPPP | 98/85/81/78 PPP- | 75/60/55/51 ---- | 50/50/50/50 ---- |
| Debussy Yver S (0.31 s) | 96/82/72/**64 PP--** | 98/83/79/69 PP-- | 79/21/18/18 P--- | 51/15/15/10 | 50/48/48/45 |
| Ravel Nicolette S (0.33 s, min 0.09 s) | 97/90/87/**83 PPP-** | 93/69/64/**54 P---** | 66/40/34/24 ---- | 47/18/18/14 | 50/50/50/50 |
| Warm-up S (0.83 s) | 99/96/94/90 PPPP | 99/95/92/86 PPPP | n/a | n/a | n/a |

¹ pro = vibrato ±50 c at 5.5 Hz, constant +10 c, per-note SD 8 c, 40 ms late entry, 60 c scoop over 80 ms, 50 ms consonant gap, 40 ms early release, 5 % detector drop-outs.
² mediocre = vibrato ±60, SD 25 c, −20 c, 120 ms late, 120 c scoop, 8 % wrong notes.

- On slow repertoire the thresholds separate pro singers (who pass L4 with 4–8 points of margin) from mediocre ones (who fail L2 and above). That is good.
- On fast repertoire, good singers fail L3/L4. The Yver ablation pins the cause: removing vibrato takes the score from 64 % to 94 %. Removing scoops, lag or offset barely matters.
- Strict L4 (18 c): even the pro scores 45–80 %. Forgiving L4: 78–97 %.

**Performance**: see section P below.

### Verified OK (no finding)
- **Timing chain sign/double-count**: correct (loopback, see above). The tracker `ctxTime = currentTime − window/2` is the right reference for a pitch estimate that needs most of the window voiced. `detectOnsets` refines to the onset edge for calibration, and both paths agree within about 1 ms (calibrated D reproduced).
- **Rate**: `scoreTimeFromCtx` applies rate after the latency subtraction (real time). L1 at 70 % tempo scores 99.3 % with a calibrated loopback. Grace and vibrato windows are in score seconds, so they get ~1.4× more lenient in real time at 0.7×. That is acceptable.
- **Simulate mode** uses `player.position` (heard time) directly and bypasses latency, which is correct for a synthetic singer. Note that it therefore never exercises the latency path; use `audio-loopback.mjs` for that.
- **Tuner / range finder** with fake-mic WAVs: A3 → "A 3 220 Hz, −2…+12 c" (vibrato ±25 c), E5 → "E 5 664 Hz". A +30 c A3 shows "A3 +28c" and then flips to "B♭3 −49c" on vibrato peaks (expected nearest-note behaviour). The range finder reports "E5 – E5" after a sustained E5.
- **Detector**: clean pitches from C2 (65 Hz) to C6 (1047 Hz), including weak-fundamental bass and a strong-2nd-harmonic soprano. Moderate breath noise (SNR ~6 dB) still tracks. Very breathy frames are gated (they do not mis-track).
- **LiveScorer complexity**: linear. 8800 samples (Yver, 175 s) push in 2.9 ms total (0.3 µs/sample), and the full `finish(samples)` re-score takes 7 ms. The `samples` array grows ~50/s (about 9k objects for the longest piece, < 1 MB), which is negligible. The highway draws only the last 400.
- **Scheduler**: `MAX_VOICES = 24` with voice stealing. Per-voice nodes disconnect `onended`, and session graph nodes disconnect 80–250 ms after stop.
