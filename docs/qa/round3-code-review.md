## Areas reviewed with no defect found

- **XSS:** no `dangerouslySetInnerHTML` or `innerHTML` anywhere. Titles, lyrics, part names and share-code names all render as React text. `sanitizeEntry` clamps share-code fields. The MusicXML DOCTYPE is stripped before `DOMParser`, so no external DTD or entity fetch.
- **Server path handling:** paths are split and decoded, and the code is regex-checked. There is no filesystem access derived from input, and the body is capped at 4 KB.
- **StrictMode double effects:** `Play.tsx`'s unmount effect and rAF loop clean up correctly. `useLibrary` is idempotent. `Tuner` autoStart is safe under a mount → unmount → mount sequence (it re-subscribes after unsubscribing). The only StrictMode impurity is CR-13.
- **Scoring time math:** sample mapping `scoreTimeAt(ctxTime − latency)` correctly includes `rate`. The count-in/HUD countdown is consistent with the player, apart from the beat length in CR-03.
- **Partial runs:** `finish()` with no completed note returns `null` and the screen goes back to Ready without logging.
- **Empty/edge scores:** `computeSections` handles zero measures. `noteRangeFor` returns null for parts with no notes in a section. `pitchWindow` handles an empty slice. `analyze` returns `[]` for no notes.

**Huge-score note:** `Math.min/max(...array)` spreads in `musicxml.ts:637,726`, `midi.ts:88,179,186` and `highway2d.ts:58` will throw `RangeError` above ~100k elements. That is unrealistic for choir scores, so it is not filed.
